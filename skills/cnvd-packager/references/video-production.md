# CNVD 复现视频零-Overlay 制作指南（参考蓝图）

本参考文档沉淀自真实过审样本（如真实浏览器 30fps + 分步神经配音管线）与典型失败反例（2fps 死图定格、跨漏洞串帧、机械 TTS 误读），供 `cnvd-packager` Stage 3B 选用本地工具链时直接对齐执行。

> **核心原则**：不绑定特定操作系统命令或某一家 TTS 供应商，但无论底层选用 Playwright + 窗口录屏、`recordVideo`、还是分步交互终端录制，都必须守住以下 **三项设计约束** 与 **六步生产流水线**。

---

## 一、三项核心设计约束

| 约束 | 目标效果 | 反例（严禁） |
|---|---|---|
| **真实操作上下文** | Web 场景用有头（headed）真实浏览器驱动真实交互，窗口包含**完整标签栏 + URL 地址栏**；API/CLI 场景分步运行并格式化输出，同时带出产品真实界面/落盘实证 | 用 `headless` 视口截图拼接（无地址栏）；用一张“已登录管理员后台图”配在“未登录基线拦截”步骤下 |
| **零 Overlay 干净像素** | 画面只呈现被测系统或终端本身；解说全部走独立音频轨，不向视频像素烧录字幕条、遮罩框或角标 | 在画面底部叠加黑底字幕条、右上角盖硬编码水印角标 |
| **Audio-First 音画同步** | 先写口播稿并合成每一步配音，拿到精确时长后反驱每一步操作停留时间：`holdMs = audio_dur * 1000 + 350ms` | 先 1~3 秒跑完整个 `poc.sh`，再用 30~40 秒静帧图硬扛整段旁白 |

---

## 二、选择采集轨道（Track）

在 Stage 1 对齐时，按漏洞载体为每个漏洞选定轨道：

### 轨道 A：Web / HTTP 控制台型（`--track web`，**默认优先轨道**）
适用：**所有具备 HTTP/Web 入口或产品控制台界面的漏洞**（包括未授权访问、登录后门、数据导出、存储型 XSS、XXE、SSRF、以及可通过浏览器地址栏/控制台操作配合验证的 SQL 注入与越权接口）。

1. **浏览器启动**：必须 `headless: false` 启动独立 Chrome/Chromium 窗口（推荐固定窗口如 `1440×810` 或 `1600×900`，`--lang=zh-CN`），保留真实标签栏与 URL 地址栏。
2. **推荐叙事结构（对标 `JFlow-精简版` 成片）**：
   - **视角切换**：未认证类漏洞先展示已登录后台退出到登录页（证明当前无会话）；越权类展示低权限账号视角；
   - **直接触发与实害落地**：直接在地址栏请求或控制台页面操作触发漏洞，**若返回 JSON/XML/源码视图或下载文件，必须清晰呈现关键字段/节点**（必要时格式化或向下滚动露出核心数据）；
   - **业务入口对照**：登录后台打开对应的控制台界面（如组织结构、流程模板库、表单模板库、抄送列表），证明受影响接口对应真实业务模块；
   - **负向对照**：在同一端点改变一个变量（如去掉 Cookie、换不存在动作 `DoType=NoSuchAction_zzz`、或对比恒真/恒假查询），证明观测结果确由缺陷本身导致。
3. **窗口级抓屏优于整屏抓屏**：
   - macOS 推荐通过窗口 ID 录制（`screencapture -v -V <sec> -l<windowid> -o -x out.mov`），避免屏保、系统通知或其它窗口意外盖住画面；
   - Linux 可使用独立 `Xvfb` 显示 + `ffmpeg x11grab`，或结合窗口级录制工具捕获完整浏览器框体。
4. **防休眠与防挂起**：
   - 录前开启防显示器休眠（如 macOS `caffeinate -d -i -s -u`，注意必须带 `-d` 并用 `pmset -g assertions` 核验生效）；
   - Chrome 启动参数建议追加 `--disable-backgrounding-occluded-windows`、`--disable-renderer-backgrounding`、`--disable-features=CalculateNativeWinOcclusion`，防止长录制时被系统挂起或杀掉；
   - 保持单会话周期置前（如每 350ms 复用同一 CDP 会话 `Page.bringToFront`），避免频繁新建会话被吞错。

### 轨道 B：纯 CLI / 非 Web 终端型（`--track cli`，**仅无 HTTP/Web 入口时降级使用**）
适用：目标完全不提供 Web/HTTP 入口（如纯本地 CLI 工具、二进制/桌面客户端、底层协议服务）。

1. **严禁「一气呵成跑 `PoC.sh` + 死图定格」**：必须把验证拆成对应分镜的独立交互阶段（基线请求 → 构造攻击载荷 → 响应展示 → 危害印证 → 负向对照），每一步清屏或分段输出，并停留到该步音频播完。
2. **响应可读性**：JSON / XML / 长报错必须经过格式化或提取核心片段（`python3 -m json.tool` / `jq` / 关键行摘录），严禁整段单行挤成一团或用 `head -c` 生硬截断关键凭据。
3. **实体闭环**：拿到权限/凭据后需再执行一次实际高权限操作或落盘文件核验印证危害。

## 三、口播脚本与 TTS 规范化

1. **独立成篇，禁用批号**：每条视频的解说词必须自洽，**禁止以「第一条」「第 4 项」等批号开头**；开头简述「目标产品名称 + 漏洞核心问题 + 当前验证视角」。
2. **TTS 术语转写表（发给配音引擎前必须过一遍）**：
   低采样 TTS 会把英文标识符、驼峰方法名和缩写读成乱码（如把 `extractvalue` 读成「二x炸出来」、`ab-inner` 读成「阿B年」、`JDBC` 读成「接近DC」）。在口播稿中应转写为可读中文或加空格/停顿提示：
   - 请求头/参数：`ab-inner` → 「内部请求头 `ab inner`」；`X-Client-Auth` → 「客户端认证头」；`sortColumn` → 「排序参数」
   - 算法/协议：`MD5` → 「M-D-5 摘要」；`AES-ECB` → 「A-E-S 电码本加密」；`JDBC` → 「数据库连接串」；`XSS` → 「跨站脚本」
   - 函数/类/配置：`extractvalue` → 「报错提取函数」；`getInterFaceImpls` → 「内省接口」；`captchaSwitch=false` → 「验证码开关为关闭状态」；`fileId` → 「文件编号」
3. **音频质量下限**：推荐神经语音 TTS（如 MiniMax TTS、`edge-tts`、OpenAI TTS 等），输出 **采样率 `>= 24 kHz`（推荐 `32 kHz`）**、清晰无明显断句杂音；避免直接用低采样生硬读屏语音。

## 四、时基对齐与无损封装（Zero-Overlay Pipeline）

当采集工具（如 `screencapture`）与配音脚本异步时，采用**首尾标定帧映射**：

1. **录前清场与状态重置**：
   - 浏览器清空 Cookie/退出到登录态，终端执行 `clear` 并等待 ≥ 0.5s 确保无上一条漏洞残影；
   - 重置易污染状态（如登录失败计数器换用全新伪造 IP、重新上传唯一命名测试文件）。
2. **首尾双色标定（如采用窗口录屏）**：
   - 录制开始先将画面切为纯绿 `#00FF00`（`CALIB_GREEN`）持续 ~0.8s，记录墙上时钟 `t_green_end`；
   - 按 `storyboard.json` 执行每一步操作并记录每步开始/结束墙上时钟，每步停留 `audio_dur * 1000 + 350ms`；
   - 全部步骤结束后切为纯蓝 `#0000FF`（`CALIB_BLUE`）持续 ~1.0s，记录 `t_blue_start`；
   - **等待抓屏进程自然结束**（勿用 `SIGINT`/`SIGTERM` 强杀 `screencapture`，否则缺失 `moov` 头导致视频损坏）。
3. **校准与混音封装**：
   - 逐帧扫描定位纯绿结束帧 `v_start` 与纯蓝开始帧 `v_end`，线性拟合 `wall = α·v + β` 得到每步在视频中的精确锚点 `anchor_sec`；
   - 裁掉首尾标定段（`trim=start_frame=..:end_frame=..`, `setpts=PTS-STARTPTS`）与空白跳转过渡；
   - 统一封装：`scale` 至 `1600:900`（或 `1440:810`）→ **`fps=30`**（最低不低于 24fps）→ `libx264 -pix_fmt yuv420p -crf 20~21`；
   - 音轨：以 `anullsrc` 铺静音底轨对齐总时长，每段配音按 `adelay=<anchor_ms>:all=1` + `amix=inputs=N:normalize=0` 精确对位，AAC `>= 128k`（推荐 `160k`）+ `-movflags +faststart`。

## 五、单轮证据同源（Single-Run Grounding）

同一漏洞的 **视频画面、`报告.docx` 内嵌截图、`截图/` 原图、`PoC.md`/`PoC.sh` 实测结果** 必须产自**同一轮干净运行**：
- 若录屏期间拿到的动态响应（如验证码明文、失败计数、临时 `fileId`、`access_token`）与早期草稿不同，以最终同轮录屏产出的实测值为准回填 `报告.docx` 与 `PoC.md`，杜绝「视频显示失败 3 次、旁白说归零、报告写失败 2 次」的交叉打架；
- `报告.docx` 嵌入的所有截图必须与 `截图/` 目录内 `.png` 文件逐字节一致（SHA-256 一一对应）。

## 六、交付前自动化质检

成片与提交包组装完成后，必须运行 `scripts/verify_cnvd_package.py`（支持单包与 `--batch` 跨包检测）且返回退出码 `0`。
